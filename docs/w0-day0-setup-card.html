从报错到跑通：9 步操作卡

针对你这台机器的实际状态写的。截图里的 SyntaxError 不是环境坏了，是命令放错了地方。
本机未安装 Miniconda 需要先装 全程约 20 分钟

01你截图里发生了什么

你在 Desktop\test\#test.py 里写了六行终端命令，然后用 D:\python.exe 去执行这个文件。Python 读到第 2 行 conda create -n ai4s python=3.11 -y，它不认识 conda 这个词，也不知道命令还能这么写，于是报 SyntaxError: Invalid syntax。

表面现象真实原因
SyntaxError 指向第 2 行那一行是 shell 命令，不是 Python 语法。Python 的语法里没有"动词 + 参数"这种写法。
终端显示 & D:\python.exeVS Code 用你点"运行"时选中的解释器直接执行了文件，跳过了 conda。
状态栏写着 Python 3.14这是系统里的另一个 Python，不是我们要的 3.11 环境。
两个附带问题，即使命令敲对了也会挂
① 文件在 Desktop\test\，但 requirements.txt 和 src/ 在 D:\WorkBuddy-output\2026-10-19-18-37-44\w0-starter\——不在同一个目录，pip install -r requirements.txt 会报找不到文件。
② 文件名以 # 开头。在 Python 里 # 是注释符，虽然文件名允许，但它在终端里也容易被当成注释截断，是个纯粹给自己添堵的命名。这个文件直接删掉。

02我查了你这台机器

检查项结果意味着
Miniconda / Anaconda未安装常见目录（用户目录、ProgramData）都没有，PATH 里也没有 conda。所以第一步是装它，不是敲命令。
系统 Python有（3.14）可以用，但版本太高。DeepChem 只支持到 3.11，先用 3.14 过 W0、以后还得重装，不如一次到位。
w0-starter 目录已存在README.md / requirements.txt / src/ / data/ 都在，等着被跑。

03九步，照着做

1
装 Miniconda
国内建议用清华镜像（快很多）：
https://mirrors.tuna.tsinghua.edu.cn/anaconda/miniconda/
选 Miniconda3-latest-Windows-x86_64.exe，一路默认即可。
安装向导里"Add Miniconda3 to my PATH"这个勾不用选——装完开始菜单会多一个 "Anaconda Prompt (miniconda3)"，用它就够，勾了反而可能污染系统 PATH。
2
打开 Anaconda Prompt，不要在 VS Code 里操作
开始菜单搜索 Anaconda Prompt (miniconda3)，右键 → 以管理员身份运行（第一次建环境更稳）。
窗口标题栏会显示 (base)，说明 conda 已经生效。
3
切到项目目录
D:
cd D:\WorkBuddy-output\2026-10-19-18-37-44\w0-starter
dir   # 应该看到 README.md、requirements.txt、src、data
Anaconda Prompt 本质是 cmd，跨盘符必须先敲 D: 再 cd。dir 能看到 requirements.txt 才算切对。
4
建环境
conda create -n ai4s python=3.11 -y
等 2–5 分钟。看到 done 和 To activate this environment, use: conda activate ai4s 就是成功。
5
激活环境
conda activate ai4s
验收：提示符前面从 (base) 变成 (ai4s)。没变就是没激活，后面装包会全装错地方。
6
装依赖
pip install -r requirements.txt
装 numpy / pandas / matplotlib / scikit-learn / openpyxl，约 2–4 分钟。结尾出现 Successfully installed ... 即可。
7
自检
python src/check_env.py
期望输出：5 行 [OK]，Python : 3.11.x，最后一行 Environment ready. Go to Day 2 (classes).
出现 [MISS] 就回到第 6 步重装。
8
跑数据脚本
python src/read_data.py
会打印 shape : (20, 7)、每列缺失数、前 5 行。这就是 Day 4 的原型——把它换成你自己的数据，任务就完成了。
9
出图
python src/make_plots.py
figures/ 下会出现三张 png。打开看一眼，能正常显示就说明整条链路通了。
全部跑通之后，再回到 VS Code
Ctrl+Shift+P → 输入 Python: Select Interpreter → 选 ai4s 那个（路径里带 miniconda3\envs\ai4s）。
这样 VS Code 里的终端和"运行"按钮才会用对解释器。但 Day 0 今晚不必做这一步——先在 Anaconda Prompt 里跑通，减少变量。

04报错对照表（存下来，前两周会反复用）

报错原文真实原因修法
SyntaxError: Invalid syntax把终端命令写进了 .py 文件命令敲在终端里；.py 里只写 Python 代码
'conda' 不是内部或外部命令用了系统 cmd / PowerShell，conda 没进 PATH换 Anaconda Prompt
No such file or directory: 'requirements.txt'当前目录不对先 cd 到 w0-starter，用 dir 确认文件在
ModuleNotFoundError: No module named 'pandas'没激活环境，或装到了别的环境conda activate ai4s 后重装；用 where python 确认路径含 envs\ai4s
'python' 不是内部或外部命令同上，环境没激活同上
pip 不是内部或外部命令conda 装的时候没带 pip，或环境没激活conda install pip
命令执行了但提示符没有 (ai4s)激活失败或激活后又开了新窗口每开一个新窗口都要重新 conda activate ai4s

05三个以后永远别做的动作

  • 不要把终端命令写进 .py。判断方法：能直接敲进黑框框执行的，就不是 Python 代码。
  • 不要用 VS Code 右上角的 ▷ 跑还不确定的文件。它会用当前选中的解释器执行，一旦解释器是系统 3.14，你的环境就白建了。先用终端 python 文件名.py 手动跑。
  • 不要往 base 环境里装包。base 只放 conda 本身，所有项目各自建 env。这是你以后不重装系统的唯一保障。
今晚的最小目标只有一个：第 7 步的 check_env.py 输出 5 行 [OK]。
只要这一行出来了，Day 0 就算过。第 8、9 步跑不通不要紧，明天再弄——但环境必须先立住。
