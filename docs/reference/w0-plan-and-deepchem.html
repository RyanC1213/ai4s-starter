Day 2 · 类（唯一必须补的语法）

# 写三个递进的类，第三个是重点
class Catalyst:
    def __init__(self, name, loading):
        self.name = name          # self 就是"这个对象自己"
        self.loading = loading

    def describe(self):
        return f"{self.name} @ {self.loading} wt%"

class SingleAtomCatalyst(Catalyst):        # 继承
    def __init__(self, name, loading, cn):
        super().__init__(name, loading)     # 调父类的 __init__
        self.cn = cn

    def describe(self):                     # 覆写
        return super().describe() + f", CN={self.cn}"

c = SingleAtomCatalyst("Pd1/Bi2WO6", 0.8, 5)
print(c.describe())

写完这个，打开 PyTorch 官方 60-Minute Blitz，只找 class Net(nn.Module) 那几段，你会发现结构一模一样：__init__ 里定义层，forward 里定义数据怎么流。不需要看懂张量运算。

三个追问，答不出两个就不是你的项目

  1. 上游那段代码是谁写的？你改了哪几个文件、哪几行？
  2. 指标从多少变到多少？为什么会变？
  3. 这个改动在化学上为什么说得通？

第 1 题考诚实，第 2 题考实验素养，第 3 题考你到底懂不懂自己的体系。三题里第 3 题是 CS 背景的竞争者答不了的——这正是你的位置。

我建议你把它做成什么

题目：小样本化学数据上，图神经网络与分子指纹基线的系统性对比

数据：MoleculeNet 里三个 <10K 的数据集（ESOL 1128 条 / FreeSolv 642 条 / Lipophilicity 4200 条）+ 你自己的光催化体系（转成表格回归任务）
模型：ECFP + RandomForest（基线） vs GCN / AttentiveFP
划分：ScaffoldSplitter（关键）
结论：给出"多小算小"的经验门槛，和一条可复用的评测规范

为什么这是好项目：DeepChem 文档自己就承认，样本量少于一 Quantity 时 GNN 常常打不过指纹基线。你在自己的体系上把这个结论量化验证——这是一个 negative result，比刷出一个好看的假高分可信得多，而且正好命中面试官最想听的那句："我知道我的方法什么时候不work。"

DeepChem 的真实状态（2026-09 核查）

项目实情
最新稳定版2.8.0，2024-04 发布，已 29 个月无新稳定版（master 仍在动，2026-08 还有 commit）
Python 支持3.7–3.11。3.12+ 会静默装成 2.5.0，报错信息完全误导
PyTorch 后端支持，但要 pip install 'deepchem[torch]'；GNN 路径还依赖 DGL / DGL-LifeSci，版本兼容是常年坑
核心价值ScaffoldSplitter + MoleculeNet 标准化评测——这两样比它的模型更值钱
结论当"评测规范 + 基线"用，不要当主线框架。主线用 PyG 或 Chemprop（更轻、维护更活跃）

明确不要做的三件事

  • Fork 别人的 repo，改 README、加个 badge、调一下 batch_size，然后写"独立开发"——一问就穿，而且是诚信问题，比能力不足严重得多。
  • 把官方 tutorial 跑一遍传到 GitHub 当项目——面试官一天能看五份一样的。
  • W0 就装 DeepChem——今晚装上大概率明天就卡在 DGL 版本地狱，第一周直接报废。Day 6 之后、仓库能跑通了再碰它。
