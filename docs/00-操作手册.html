01装 Miniconda

这是唯一需要下载安装包的一步。装完之后，所有 Python 相关的事都在它的终端里做。

STEP 1下载并安装 Miniconda约 10 分钟
去哪里
浏览器打开清华镜像：
https://mirrors.tuna.tsinghua.edu.cn/anaconda/miniconda/
在列表里找 Miniconda3-latest-Windows-x86_64.exe，点它下载。
怎么做
双击安装包，一路点 Next，但在这两个地方停一下：
  • 安装路径：保持默认（C:\Users\Administrator\miniconda3）。路径里不要有中文、不要有空格。
  • "Add Miniconda3 to my PATH environment variable" → 不勾。
  • 最后 "Register Miniconda3 as my default Python" → 可勾可不勾，勾了也不影响。
应该看到
安装完成后，开始菜单里出现一个文件夹 "Miniconda3 (64-bit)"，里面有 Anaconda Prompt (miniconda3)。这就够了。
为什么
  • 为什么用镜像不用官网：官网在国内经常几十 KB/s，镜像能跑满带宽。同一个文件，官方要 40 分钟，镜像 3 分钟。
  • 为什么不用 Anaconda：Anaconda 装完 3–5 GB，预装几百个你这辈子不会用的包。Miniconda 只有 conda + Python，200 MB。你要什么装什么。
  • 为什么不勾 PATH：你机器上已经有一个 Python 3.14（VS Code 之前用的就是它）。把 conda 塞进 PATH 会让这两个抢"谁是 python"，最典型的症状是——你明明激活了环境，python 却还是 3.14。不勾 PATH，用专用的 Anaconda Prompt，两者互不干扰。
出错了
安装到一半报"写入失败"→ 右键安装包选"以管理员身份运行"。
装完开始菜单搜不到 → 重启一次资源管理器，或在 C:\Users\Administrator\miniconda3\Scripts 里找 activate.bat。
⚠️ 最容易犯的错：从镜像目录里点了老版本
清华镜像的目录是按文件名排序的，Miniconda3-py38_4.8.2、Miniconda3-py39_4.9.2 这些 2020–2021 年的老包排在最前面，Miniconda3-latest 反而在中间。顺手点第一个 = 装回五年前。

判断标准：装完在 Anaconda Prompt 敲 conda --version，主版本号应该是 25.x。如果显示 4.9.2、4.12.0 这类，就是装错了。

装错了怎么办：干净重装（5 步）

老版 conda 不能靠"升级"救回来——conda 4.9.2 的依赖求解器不认识 2026 年的 repodata 格式，你后面跑 conda create -n ai4s python=3.11 大概率直接 Solving environment: failed。重装比修复快得多，也更干净。

步做什么为什么 / 注意
1 关掉所有终端窗口、VS Code、Jupyter 有进程占用文件时卸载会失败或残留
2 运行 C:\ProgramData\miniconda3\Uninstall-Miniconda3.exe 用这个卸载器，不要直接删文件夹。直接删会留下注册表项和开始菜单快捷方式，下次装的时候会打架
3 确认 C:\ProgramData\miniconda3 已经消失；再检查 C:\Users\Administrator\.conda 和 .condarc，有就删掉 这两个是用户级配置，卸载器不管。不删的话，新装的 Miniconda 会继承旧配置
4 重新下载 Miniconda3-latest-Windows-x86_64.exe 文件名里必须带 latest，不要带 py38 / py39 / 版本号
5 安装时选 Just Me（装到 C:\Users\Administrator\miniconda3）；不勾 Add to PATH；不勾 Register as default Python 为什么这次选 Just Me：装在 ProgramData 是"所有用户"安装，之后每次 pip 装包都要管理员权限，麻烦不断
重装完的验收标准
打开新的 Anaconda Prompt (miniconda3)，敲 conda --version → 显示 conda 25.x.x；敲 python --version → 显示 Python 3.1x.x（base 里是 3.12 或 3.13 都正常，不重要——你要的 3.11 是在 STEP 4 新建环境时指定的）。
两条都对，就可以继续 STEP 2。

02打开正确的终端

STEP 2用 Anaconda Prompt，不要用 VS Code 的终端1 分钟
去哪里
Windows 开始菜单 → 直接输入 anaconda → 出现 Anaconda Prompt (miniconda3) → 点开。
怎么做
打开后什么都不用做，先看提示符长什么样。然后敲一条命令确认： 
conda --version
应该看到
窗口最左边显示 (base)，命令提示符类似：
(base) C:\Users\Administrator>
敲完 conda --version 返回 conda 25.x.x 之类的版本号。
为什么
  • 为什么不用 VS Code 的终端：VS Code 默认终端是 PowerShell，它不会加载 conda 的初始化脚本。你在里面敲 conda 会得到"不是内部或外部命令"。这不是 conda 坏了，是你在错误的房间里。你之前那个 SyntaxError 的截图，就是在 VS Code 里操作的。
  • 为什么先看提示符：(base) 这两个字是"conda 已生效"的唯一证据。后面每一步都要靠提示符判断你在哪个环境里。
出错了
'conda' 不是内部或外部命令 → 你开的是 cmd 或 PowerShell。关掉，回来用开始菜单里的 Anaconda Prompt。

03进入 project 目录

STEP 3把终端"站"到项目文件夹里1 分钟
去哪里
还是在 Anaconda Prompt 里。目标目录是 C:\Users\Administrator\Desktop\project。
怎么做
cd C:\Users\Administrator\Desktop\project
dir
如果桌面路径不是这个（比如 OneDrive 重定向过），先在文件资源管理器里打开 project 文件夹，点一下地址栏，把路径复制下来，再 cd 过去。
应该看到
dir 列出这些东西：README.md、requirements.txt、src、data、docs、figures、sync.bat。
看不到 requirements.txt 就是没切对目录。
为什么
  • 后面的 pip install -r requirements.txt 和 python src/xxx.py 都是相对当前目录找文件的。不在这个目录，它会报 No such file or directory——你之前那个报错里就有这一层。
  • 另外，脚本里用 pathlib 按"脚本所在位置"推路径，所以你从哪个目录启动都不该崩；但养成"先 cd 到项目根"的习惯，能省掉 90% 的路径问题。
出错了
系统找不到指定的路径 → 桌面被 OneDrive 接管了，真实路径可能是 C:\Users\Administrator\OneDrive\Desktop\project。用资源管理器地址栏复制真实路径。
小技巧：在资源管理器里打开 project，点地址栏输入 cmd 回车，会直接在该目录开一个终端。

04建 conda 环境

STEP 4创建一个叫 ai4s 的独立环境2–5 分钟
去哪里
Anaconda Prompt，仍在 project 目录下。
怎么做
conda create -n ai4s python=3.11 -y
等它跑完。会下载 Python 3.11 和一批基础依赖，大约 100–200 MB。
应该看到
进度条走完，出现 done，最后两行类似：
To activate this environment, use
conda activate ai4s
为什么
  • 为什么是 3.11，不是 3.13/3.14：MACE 要求 ≥3.11；而 3.12 以后不少科学计算包（尤其是需要编译的）还没跟上。3.11 是 2026 年这个生态里最稳的版本，几乎所有 AI4Science 项目都在 3.10/3.11 上测过。
  • 为什么不用系统那个 3.14：一是版本太高，二是你迟早会把某个包装崩——装在独立环境里，崩了删掉重建，5 分钟的事；装在系统里，崩了就是重装 Python。
  • 为什么不装进 base：base 是 conda 自己的家。往里面装东西，装得越多越容易坏，而且坏了没得修。base 只放 conda，项目各建各的，这是唯一能让你三年不用重装系统的纪律。
出错了
卡在 Solving environment 很久 → 正常，第一次可能 3–5 分钟。
CondaToSNonInteractiveError → 见下方专门一节，这是 2025 年后必踩的新坑。
⚠️ 2025 年后新增的坑：CondaToSNonInteractiveError
报错长这样：
CondaToSNonInteractiveError: Terms of Service have not been accepted for the following channels:
- https://repo.anaconda.com/pkgs/main
- https://repo.anaconda.com/pkgs/r
- https://repo.anaconda.com/pkgs/msys2

为什么会这样：2025 年 7 月起，Anaconda 改了服务条款，给 conda 装了一个叫 conda-anaconda-tos 的插件。你第一次使用 defaults 渠道时装包，它要求你明确同意条款。
如果你在终端里手动敲命令，它会弹一个 Do you accept? 让你回答；但你的命令里带了 -y（自动回答 yes），conda 没有机会弹窗，就直接判为"未同意"并中止。

后果：环境根本没建出来。所以紧接着的 conda activate ai4s 会报 EnvironmentNameNotFound——那不是第二个错误，是同一个错误的回响。

许可说明（放心）：个人使用、学术研究免费。只有当你的公司是 200 人以上的营利机构时才需要买商业许可。你是博士生，正常接受即可。

解法：先接受条款，再建环境

在 Anaconda Prompt 里逐条复制粘贴下面三行（URL 很长，别手打）： 

conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/main
conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/r
conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/msys2

执行后不会有成功提示，直接回到提示符就是成功了。然后重新执行 STEP 4：

conda create -n ai4s python=3.11 -y
conda activate ai4s
python --version
这一步的"为什么"值得记住
这类报错最容易让人怀疑自己操作错了。判断方法：看报错里有没有出现"Terms of Service""license""accept"这类字眼——出现就说明是合规/授权问题，不是语法问题，命令本身没写错。
顺带一提，学术界更常用的替代方案是 conda-forge 社区渠道（无 ToS 限制、包更新更快）。等你熟悉 conda 之后可以切过去；现在先别动，一次只改一个变量。

06装 GPU 版 PyTorch（最关键的一步）

你前面所有步骤都是准备工作，真正的技术陷阱在这一步。装错这一个包，后面全部报错，而且报错信息会误导你。

STEP 6装 cu128 版 PyTorch下载约 2.5 GB
去哪里
Anaconda Prompt，提示符是 (ai4s)，目录是 project。
怎么做
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128
下载 + 安装 5–15 分钟，取决于网速。中途不要关窗口。
应该看到
结尾 Successfully installed torch-2.x.x+cu128 ...
确认一下：pip show torch，Version 那一行必须带 +cu128。
为什么
  • 为什么必须带 --index-url：PyPI 默认给你的是CPU 版。不加这个参数，装完也能 import，但 GPU 完全用不上——这是新手最常见的"我的显卡好像没生效"。
  • 为什么必须是 cu128：你的 5060 Ti 是 Blackwell 架构，代号 sm_120。cu121 / cu124 / cu126 这些轮子在编译的时候 sm_120 还不存在，所以里面没有对应内核。升级驱动也救不了——缺的是编译进去的机器码，不是驱动版本。
  • 为什么不用装 CUDA Toolkit：cu128 的 wheel 里已经打包了 CUDA runtime 和 cuDNN。你只需要显卡驱动够新（R570 以上）。网上让你先装 3 GB Toolkit、配环境变量的教程是 2020 年的做法，现在照做只会多三个故障点。
出错了
网速极慢 → 加国内镜像（不推荐，镜像的 cu128 轮子常不全）；更稳的是挂代理。
Could not find a version that satisfies → 检查是不是拼错了 cu128。
装完 pip show torch 没有 +cu128 → 你没加 --index-url，重来。

07验证 GPU（不要跳这一步）

STEP 7跑 check_gpu.py30 秒
去哪里
Anaconda Prompt，(ai4s) 环境，project 目录。
怎么做
python src/check_gpu.py
应该看到
==========================================================
Python : 3.11.x
torch  : 2.x.x+cu128
cuda   : 12.8
==========================================================
GPU    : NVIDIA GeForce RTX 5060 Ti
算力   : sm_120
显存   : 7.9 GB
编译架构: sm_75 sm_80 sm_86 sm_90 sm_100 sm_120
含 sm_120 内核: 是
----------------------------------------------------------
[OK] fp16 矩阵乘 512x512 : 中位数 0.065 ms (min 0.063)
[OK] fp16 矩阵乘 2048x2048: 中位数 0.423 ms  ≈ 40.6 TFLOPS
     (RTX 5060 Ti 参考值：30–50 TFLOPS，明显低于 20 说明有问题)
[OK] 训练一步           : loss=1.0719
==========================================================
VERDICT: GPU 可用，可以进入 W1。

以上是这台机器（RTX 5060 Ti 8 GB / torch 2.11.0+cu128）的实测值，你的输出应该基本一致。

为什么
  • 因为 torch.cuda.is_available() 会撒谎。它只检查"系统有没有看到显卡"，不检查"PyTorch 里有没有这张卡能用的内核"。装错版本时它照样返回 True，tensor.cuda() 也照样成功——因为分配显存不需要计算内核。直到你真正做一次矩阵乘，才会炸出 no kernel image is available。
  • 所以这个脚本做的两件事——fp16 矩阵乘、训练一步——才是唯一有效的验收。看到 [OK] 这两个字，你才算真的能用 GPU。
  • 为什么脚本要先"预热"再计时：第一次 CUDA 运算会初始化 cuBLAS 并加载 sm_120 内核，这一步要花十几秒。如果直接计时，0.065 ms 的运算会被测成 696 ms——这个数字真实出现过，当时差点误判成"显卡有问题"。所以脚本先空跑 10 次，再逐次计时取中位数。以后你测任何 GPU 性能，都要先预热。
  • 如果这一步过了，你就绕过了 90% 的 50 系用户会踩的坑。
出错了
no kernel image is available → 装的是非 cu128 版本，卸了重装：
pip uninstall -y torch torchvision torchaudio 然后回第 6 步。
Torch not compiled with CUDA enabled → 装成 CPU 版了，同上。
Found no NVIDIA driver → 驱动太旧，去 NVIDIA 官网更新。

怎么做
pip install -r requirements.txt

09装 MACE 与 ASE

STEP 9装通用势函数框架3–5 分钟
去哪里
Anaconda Prompt，(ai4s) 环境，project 目录。
怎么做
pip install "mace-torch==0.3.*" ase
引号不能省。在有些 shell 里 ==0.3.* 会被当成通配符展开。
应该看到
Successfully installed mace-torch-0.3.x ase-3.x ...
跑 pip show mace-torch 确认版本以 0.3 开头。
为什么
  • 为什么锁 0.3.*：MACE 的 v1.0 正在 mace-reforge 分支重写，官方明确写了"不保证兼容，检查点要通过转换器迁移"。你直接 pip install mace-torch 装 latest，有可能进到一条还在天天变的代码线上，网上搜到的教程全部对不上。
  • 为什么装 ase：MACE 本身只负责"给结构算能量和力"，是 ASE 提供了"读 CIF、做弛豫、存轨迹"这一整套原子模拟的通用接口。两者是"引擎 + 车架"的关系。
  • 为什么不装 cuequivariance、flash-attn：这些是加速插件，需要本地编译，Windows 上环境要求苛刻。它们能让你快 20%，但会让你卡三天。现在不需要。
出错了
Microsoft Visual C++ 14.0 required → 某个依赖想本地编译。装 "Microsoft C++ Build Tools" 太重；更好的做法是先看是哪个包，很多情况下换个版本就不用编译。
装完 pip 说 "Attempting uninstall: torch" → 立刻警惕，见下一步。

10装完 MACE 后重验 GPU

STEP 10再跑一次 check_gpu.py30 秒
去哪里
同一个终端。
怎么做
python src/check_gpu.py
pip show torch
应该看到
和第 7 步完全一样的输出：VERDICT: GPU 可用，且 pip show torch 里仍然带 +cu128。
为什么（这一步最容易被跳，也最容易出事）
  • pip 在装 MACE 时会重新解析依赖树。如果 MACE 声明的是 torch>=2.0 而你装的是 2.13，理论上不会动；但如果某个传递依赖对 torch 有版本上限，pip 会"贴心"地帮你降级到它满意的版本——而那个版本很可能不带 cu128 轮子。
  • 降级是静默的。你不会看到报错，只会在第 11 步遇到一堆莫名其妙的 CUDA 错误，然后怀疑人生。
  • 规则：每次 pip install 大包之后，都重跑一次 GPU 自检。这条习惯能帮你省掉未来 80% 的玄学问题。
出错了
GPU 挂了 → pip install --force-reinstall torch --index-url https://download.pytorch.org/whl/cu128，再验证一次。

11第一次真实计算

从这一步开始，你不再是在"装环境"，而是在做 AI4Science 了。

STEP 11用 MACE 弛豫 18 原子 Bi₂WO₆首次下载权重 2–5 分钟
去哪里
Anaconda Prompt，(ai4s) 环境，project 目录。
结构文件已在 data/structures/。
怎么做
python src/relax_bi2wo6.py --gpu
第一次跑会下载 MACE-MP 权重（几百 MB）。屏幕可能静止 2–5 分钟，那不是死机，是在下载。
应该看到
结构   : Bi2WO6_ICSD23584.cif
原子数 : 18 | Bi4O12W2
晶胞   : a=8.917 b=8.917 c=5.548 Å
设备   : cuda
加载 MACE 权重...
----------------------------------------------------------
初始能量 : -xx.xxxx eV  (-x.xxxx eV/atom)
初始最大力: x.xxx eV/Å
开始弛豫 (BFGS, fmax=0.05, 最多 300 步)...
      Step     Time          Energy         fmax
...
----------------------------------------------------------
弛豫后能量 : -xx.xxxx eV  (-x.xxxx eV/atom)
弛豫后最大力: 0.0xx eV/Å
能量下降   : 0.0xxx eV/atom
是否收敛   : 是
已保存     : data\relaxed\Bi2WO6_23584_relaxed.cif
为什么
  • "弛豫"是什么：晶体里原子不是随便待着的，它们会往能量最低的位置挪。弛豫就是让每个原子受的力趋近于零（fmax < 0.05 eV/Å），得到稳定的几何结构。你以后算吸附能、算反应路径，前提都是结构已经弛豫好——拿一个没弛豫的结构去算能量，结果没有意义。
  • 为什么这件事重要：传统上这一步要用 DFT，18 个原子大概几小时到几天。MACE 用预训练神经网络势函数，把它压到几十秒。这就是 AI4Science 最朴素的形态——不是让 AI 写论文，是让 AI 把 DFT 的重复劳动加速 1000 倍。
  • 为什么先用 18 原子：它是原胞，最小、最快，用来验证"整条链路通不通"。先跑通再谈精度。
出错了
AttributeError: module 'mace.calculators' has no attribute 'mace_mp' → 版本太老/太新。跑 python -c "import mace; print(mace.__version__)" 看版本，必要时 pip install "mace-torch==0.3.14" 指定具体版本。
权重下载卡 0% → set HF_ENDPOINT=https://hf-mirror.com 后重跑。
CUDA out of memory → 18 个原子不可能 OOM，说明是别的程序占了显存（游戏/浏览器硬件加速），关掉再跑。

12第二次计算与交叉验证

STEP 12弛豫 36 原子常规胞，对比两者能量1–2 分钟
去哪里
同一个终端。
怎么做
python src/relax_bi2wo6.py --gpu --cell 67647
python src/compare_relax.py
⚠️ 不要对 .cif 调 get_potential_energy()，会报 Atoms object has no calculator。
CIF 只存几何结构（晶胞 + 坐标），不存能量；能量存在 .traj 轨迹里，ASE 读轨迹时会自动挂上计算器。compare_relax.py 已经处理好了这件事。
应该看到
18 原子原胞      relax_23584.traj   n=18   -6.6010 eV/atom  (来源: 轨迹)
36 原子常规胞    relax_67647.traj   n=36   -6.6011 eV/atom  (来源: 轨迹)
--------------------------------------------------------------
每原子能量差: 0.14 meV/atom
判定: [自洽] 两种取胞等价，弛豫充分，可以往下做表面模型。
--------------------------------------------------------------
18 原子原胞      a=8.917 b=8.917 c=5.548 Å  V=262.1 Å³  (输入 CIF V=262.1)
36 原子常规胞    a=5.530 b=5.569 c=16.955 Å  V=522.2 Å³  (输入 CIF V=522.2)

以上是这台机器的真实输出。能量差 < 3 meV/atom 就算通过。

为什么这个对比有意义
  • 18 原子和 36 原子是同一个晶体的两种取胞方式，物理上完全等价。所以每原子能量必须一致。如果差很多，说明某个结构没弛豫干净，或者取胞时原子位置有问题。
  • 这是一个零成本的自我检验。很多人在这一步不查，带着一个坏结构往下算吸附能，最后结果全错却找不到原因。
  • 面试价值："我用两种取胞做了交叉验证，每原子能量差 1.8 meV"——这句话直接证明你懂"怎么判断计算靠不靠谱"，而这正是 non-CS 背景的人最容易欠缺、也最容易被追问的地方。
出错了
差值 > 10 meV/atom → 大概率没收敛。加大 --steps 600 或放宽 --fmax 0.08 重跑。
差 0.05 eV 以上 → 结构读错了，检查晶胞参数是否和 data/structures/README.md 一致。

安装过程中只有一处要停下来选：

为什么这次要"勾 PATH"，而装 conda 时却让你别勾？
因为两者的问题不一样：
  • conda 会往 PATH 里塞一整套 Python。你机器上已经有一个 Python 3.14 了，两个抢"谁是 python"会出乱子 → 所以不勾，用专用终端。
  • Git 只有一个版本、不会和任何东西冲突，而且 VS Code、各种工具都要调它。官方默认就建议装进 PATH → 勾上。
判断标准不是"永远别勾 PATH"，而是"这东西会不会和已有的东西抢同一个名字"。
装完必须做两件事
① 关掉当前 Anaconda Prompt，重新开一个。PATH 的修改只对新开的进程生效，老窗口里敲 git 还是会报同样的错。

② 配置身份（不配的话 git commit 会拒绝执行）：
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@xxx.com"
建议用 GitHub 账号绑定的邮箱，这样提交记录能关联到你的主页。
